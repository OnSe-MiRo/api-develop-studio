# 케이스 호출과 실행 결과 저장

새 케이스는 **API 호출만**이 기본이다. URL을 입력하고 실행하면 기대 응답을 작성하지 않아도 호출할 수 있다. OpenAPI 예시를 불러와도 호출 모드는 유지한다. HTTP 4xx·5xx는 수신 결과로 표시하고, 연결 오류·timeout은 오류로 처리한다.

검증하려면 **응답 검증**을 선택한다. 기대 status는 항상 검사하며 본문 일치·변수 조건·응답 시간·OpenAPI 계약은 선택 설정에 따른다. 이전에 저장한 케이스는 기존 검증 방식으로 열린다. 화면에서 모드만 전환하면 입력값을 유지한다. 호출 모드로 저장하면 검증 설정을 제외해 저장하므로, 저장된 케이스를 다시 불러올 때 검증 설정은 복원되지 않는다.

## 호출 정보

실행 결과에서 HTTP 상태, 소요 시간, 응답 본문을 바로 확인한다. 단계별 결과와 실행 로그는 **실행 상세 결과 보기**를 눌러 펼친다. 저장된 결과는 **저장 결과 보기**를 눌러 목록을 연다. 두 영역은 기본적으로 닫혀 있으며 현재 호출 응답·오류·저장/다운로드 버튼은 계속 표시된다. **요청 정보 · 헤더 / 본문**과 **응답 헤더**를 펼쳐 상세를 본다. 요청은 Base URL, 변수, 인증이 적용된 전송 직전 값이다. HTTP 라이브러리가 추가하는 자동 헤더와 리다이렉트 중간 요청은 포함하지 않는다. multipart 파일은 경로·파일명 등의 메타데이터만 담고 파일 내용은 기록하지 않는다.

인증값과 보안 변수, 알려진 민감 필드 이름은 기존 로그 규칙에 따라 마스킹한다. 직접 넣은 Authorization·Cookie·API key 및 민감 쿼리 값의 응답 반사도 마스킹한다. 일반 응답 데이터 전체를 익명화하는 기능은 아니다.

## 저장과 재조회

- **실행 결과 JSON 다운로드**: 완료·실패·오류·timeout·취소된 실행의 수집된 요청/응답, 시간, 결과, 로그를 JSON 파일로 내려받는다. 현재 편집 중인 입력값으로 덮어쓰지 않는다.
- **실행 결과 앱에 저장**: 단일 케이스 실행 당시 서버 결과를 DB에 명시 저장한다. 저장한 결과는 임시 작업 만료나 서버 재시작 후에도 남는다. 같은 Run ID를 다시 저장해도 중복 생성되지 않는다.
- **저장한 실행 결과 → 저장 결과 선택**: 같은 프로젝트·케이스 경로에 대해 현재 사용자와 workspace가 저장한 최근 100개 결과를 다시 연다. 저장 결과에서도 JSON 다운로드가 가능하다. 케이스를 저장하지 않고 실행한 결과도 당시 경로에 연결된다.

저장하지 않은 임시 실행은 기존 보존 기간(기본 600초) 또는 완료 작업 수 제한에 따라 만료된다. 앱에 보관하려면 만료 전에 저장해야 한다. 앱 저장은 최대 4 MiB이며, 기존 실행 출력 한도 1 MiB를 넘으면 잘린 범위만 보관된다. JSON 다운로드의 `incomplete` 및 화면 로그에서 잘림을 확인할 수 있다. 저장 결과 목록은 최신 100개를 표시하고 이전 결과 자체를 삭제하지 않는다.

DB migration 7이 별도 `saved_run_results` 테이블을 추가한다. 기존 실행 대시보드 이력은 계속 메타데이터만 보관한다. 저장·조회는 서버의 사용자/workspace 권한을 적용한다. 케이스 파일 구조 `case/{tag}/{api_name}/{case_file}.json`은 유지한다.
