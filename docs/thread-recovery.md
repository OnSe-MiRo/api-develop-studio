# 로컬 요청 스레드 회복 검증

기준 `develop 654515d`의 이전 35 VU 시험은 부하 구간을 완주했으며, 사후 5분 평균 스레드 2.58→4.00으로 120% 회복 기준을 넘었다. [이전 기록](case-list-recovery.md)

실제 HTTP 요청 6개를 동시에 처리하고 유휴 상태로 두는 회귀에서, 기존 AnyIO 요청 worker 6개가 11초 뒤에도 살아 있었다. AnyIO는 새 요청을 배치할 때 유휴 worker를 정리한다. 새 앱별 요청 풀은 worker 최대 40개와 기존 AnyIO 호출 admission을 사용하며 1초 동안 대기 작업이 없는 worker를 종료한다. 정상 요청에 이어 예상 409를 반환하는 회귀에서는 동기 오류 응답 함수가 별도의 AnyIO worker를 남겼다. JSON 오류 응답을 async handler로 등록해 이 경로를 정리했다.

요청 풀은 각 작업에 인증 ContextVar를 복사한다. 취소된 호출의 실제 작업이 끝날 때까지 admission을 유지하고, 종료는 대기 작업 처리·취소와 실행 작업 완료를 기다린다. 함수 예외와 스레드 시작 실패 뒤에도 대기 상태를 정리한다. 작업 실행용 `JobManager`와 HTTP 요청 처리 풀은 각각의 수명주기를 갖는다. 사용자별 작업 조회와 실행 슬롯 정책은 [실행 안내](async-runs.md)를 따른다.

검증은 격리된 SQLite Medium 스냅샷에서 실제 loopback HTTP로 수행한다. 기본 35 VU·7,200초 profile과 같은 서버의 전후 5 VU·300초 기준선을 비교하고, 원래의 오류·부하 중단 조건과 120% 회복 기준을 적용한다. 스레드 이름·native ID는 진단용 loopback 공급자에서만 수집한다. P1의 v1·v2 지문으로 측정한 과거 결과를 재현하며 새 측정은 요청 풀 소스를 포함한 v3 지문을 요구한다.

## 정규 35 VU·2시간 재검증 (2026-11-09)

고정 후보 `9099690d723a4aa5993d723dbc885db30a528893`는 기준 develop `654515d`에서 분기했다. 깨끗한 detached checkout에서 09:02:53~11:03:28 KST에 정규 profile과 사후 무결성 검사를 수행했고, 같은 서버에서 11:03:28~11:08:48에 사후 5 VU·300초와 정리 검사를 수행했다. 생성 fixture와 설치 패키지·모듈 지문은 전후 동일했다. [기계 판독 결과](thread-recovery.json)

- 부하 구간은 35 VU·7,200초를 완주했다. 35 VU 표본 7,200개의 최초~최종 간격은 7,198.982초이며 중단 사유는 없다. 요청·timeout·중단 기준과 120% 회복 기준은 유지했다.
- 전체 HTTP 142,535건 중 200은 136,823건, 예상 revision 충돌 409는 5,712건이었다. 동기 실행 7,059건은 모두 200이며 DB의 고유 성공 Run ID·exit 0 수와 일치한다. 429·예기치 않은 오류·실행 실패·실패한 check는 0건이었다.

## 회귀 및 증거 보존

최종 고정 후보에서 PostgreSQL·Redis를 포함한 Python 전체 740개(123.421초), 프런트엔드 169개/38파일, production build, 생성 서버·LT-5·과거 P1 보고서 재현과 k6 모델 5개가 통과했다. build의 기존 chunk 크기 경고는 남아 있다. 유휴 회수·오류 응답·인증 문맥·취소·queue 한도·시작 실패·앱 재사용·중첩 lifespan·종료 예외 회귀를 포함한다.

첫 120초 진단의 별도 오류 handler worker 잔류 실패와 두 번째 진단의 회복 통과도 보존했다. 전체 회귀에서 발견했던 앱 재사용·중첩 수명주기 실패는 수정 이력과 함께 두 진행 문서에 남겼다. 축소 진단은 정규 2시간 결과와 구분한다.

원본 k6 JSONL·phase·서버 로그·자원 표본·실행 이력 증명과 환경 지문은 로컬 `data/load-test-evidence/thread-recovery-9099690-20261109/`에 보존했다. 압축 입력 61개를 원본 바이트 지문과 대조하고 29개 파일 체크섬을 검증했다. `sha256.json` 자체 SHA-256은 `0f7932afe13cb4cf7bad266b194725fcc8652aa2424aee45a24823925082f1a9`다. 검증 기록 이후 커밋은 문서만 변경하며 실제 검증 제품 소스는 `9099690`과 동일하게 유지한다.
